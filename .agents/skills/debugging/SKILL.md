# 不具合の原因調査と修正

共通規約・不変条件・検証範囲はルートの `AGENTS.md` に従う。コード・運用パスはリポジトリルート基準、以下の Markdown リンクは本 Skill からの相対パス。

症状を説明する証拠と再現条件を特定する。修正依頼では原因の修正・再現ケースの解消・必要な回帰検証まで進め、調査のみなら確認できた原因と未確認事項を報告する。

## 症状に応じた参照

必要な行だけを選ぶ。専門 Skill で調査が完結する場合は、同じ調査を重ねない。

| 症状 | 参照先 |
|---|---|
| 予期しない `w_final=0`、PIT 履歴不足 | [フラット・PIT の診断](references/flat-and-pit.md) |
| `df_exec` 切断、NaN、キャッシュ鮮度の異常 | [データ・キャッシュの診断](references/data-and-cache.md) |
| 指標の異常、本番との乖離、特定日のウェイト根拠 | [指標比較・シグナルトレース](references/metrics-and-trace.md) |
| 監査失敗・リーク疑い | [leak-audit](../leak-audit/SKILL.md) |
| ハング・ロック・注文確認待ち | [hang-prevention](../hang-prevention/SKILL.md) |

## 再現と計測

- 対象日、コード版、有効設定、入力データ版、ログを揃え、原因の切り分けに必要な範囲へ絞る。ローリング窓・事前分布・PIT の履歴は、評価期間を短くしても確保する。
- 日次バッチは実注文・データ更新を含み得る。再現前にコマンドと副作用を確認し、保存入力や合成 fixture を使う。既存バッチをそのまま再実行することを診断手順にしない。
- 計測には既存 logger と中間値を使う。再現用コードを残す場合は `src/research/scripts/experiments/`、一時ファイルは一時ディレクトリ、証跡は `reports/<作業名>/` に置く。`var/live/pipeline_data/` へデバッグ出力を書かない。
- 数値比較では有限性と誤差の根拠も確認する。`equal_nan=True` は欠損自体が期待される比較に限り、NaN を正常値として隠さない。

テスト失敗は対象ケースを先に再現する。並列時だけ失敗するなら、直列との違いから共有キャッシュ・fixture・ファイル/ロック・一時パスの競合を調べる。全体回帰と停止期限は AGENTS.md に従い、分割実行スクリプトだけで全テスト完了としない。

## 完了の根拠

原因を支える観測、再現ケースの結果、修正した範囲、実行した検証と未確認事項を残す。既存テストに不足がある場合は [test-gen](../test-gen/SKILL.md) で回帰ケースを追加する。一時的な計測コードは整理し、再現に必要な証跡は保持する。設計上の理由は `docs/decisions/`、調査結果は `reports/`、再利用できるハング復旧手順は `docs/スタック再発防止策.md` へ記録する。
